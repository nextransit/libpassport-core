# 1380 样本合规 review（对照 gray_training_outline_1105.md v1.2，2026-11-06）

按 `ai-research-skills-mrz` §4/§8 与大纲 §2/§4/§6 执行。结论先行：

> **GUI「MRZ OCR测试」当前那 1380 张（`6_mrz_ocr/data/corpus_eval`，seed=2002，随机内容）
> 不符合训练大纲的样本规范**，而且它的低 exact 率**主要不是模型不行**，是语料本身同时踩了
> 三条线：① 内容非 plausible（与解码先验对抗）；② 渲染是准二值（不度量真实成像）；
> ③ 无 §6.1 要求的四级分层、且大纲明文禁止用它给 Blurry/Reflective 档打分。
> 已实测：同一份权重在 plausible 语料上 full exact **17.75% → 73.47%**（cnn）。

## 1. 实测基线（当前发布权重 40951c5）

| 语料 | engine | l1 逐字 | l2 逐字 | **full exact** | cksum valid |
|---|---|---|---|---|---|
| **旧 1380**（GUI 当前，seed 2002，随机内容） | cnn | 91.94% | 94.61% | **17.75%** | 99.06% |
| | crnn | 92.14% | 95.73% | **16.59%** | 99.93% |
| plausible v2（1440，k_iso3 池 + 日历合法日期） | cnn | 95.78% | 95.38% | **73.47%** | 95.97% |
| | crnn | 96.37% | 97.33% | **74.93%** | 97.15% |

旧 1380 的「cksum 99% 但 full 18%」是随机内容语料的典型症状：校验位由构造保证，
改一个非校验位字符仍能过校验 → 结构对、字符错。

## 2. 逐条合规核对（大纲 §4 / §6）

| 大纲条款 | 要求 | 旧 1380 实测 | 判定 |
|---|---|---|---|
| §4.1 字体级抗锯齿 | TrueType 渲染 + 字体级 AA，禁 `INK_THRESHOLD` 硬阈值 | 1-bit 字模（`INK_THRESHOLD=128`）+ 一次 `blur3` 生成 16 级边缘；全图仅 12 个灰度级 | **不符** |
| §4.1 前景/背景动态灰度 | 前景 [20,110]、背景 [180,245]，按笔画采样 | 固定 0/255；84.45% 像素是纯端点 | **不符** |
| §4.1 笔画不均匀 / gamma / 边缘晕染 | 乘性系数 [0.85,1.15]、脏污 ≤5%、γ∈[0.8,1.25]、高斯晕染 | 全部缺失 | **不符** |
| §4.2 真实护照底纹融合 | 真实照片无字区底纹切片库 + 固化公式 | 仅 `gen_cscd_synthetic.py` 的程序化 sin/cos（且只在 CS/CD 脚本里）；主链路无 | **不符** |
| §4.3 S1 灰度渲染 | 字体级 AA | 见 §4.1 | **不符** |
| §4.3 S2 墨色不均匀 | 笔画级 | 无 | **不符** |
| §4.3 S3 底纹融合 | 真实底纹 | 无 | **不符** |
| §4.3 S4 光照场 | 线性 illum 0–80（≥40 占 ≥30%）、二维高斯高光 + clip | 仅线性渐变（墨迹不变暗）+ 背景渐变 | **部分** |
| §4.3 S5 几何 | 旋转 ±3°、剪切 ±0.03、透视 ≤2%W，**置于模糊之前** | 仅旋转 ±3°；且现状是「先 blur3 后最近邻 rotate」——**顺序错误且重引入锯齿** | **不符** |
| §4.3 S6 光学模糊 | 高斯（显式 σ）+ 运动模糊 3–9px | 仅 3×3 二项式模糊 pass，无运动模糊 | **部分** |
| §4.3 S7 传感器噪声 | 加性高斯 σ∈[1,6]/255 + 暗电流 + 椒盐 | 纯 0/255 椒盐翻转（50% 概率），无高斯/暗电流 | **不符** |
| §4.3 S8 下采样 + JPEG | 双线性 filter=true（与 fastPair 红线一致）+ JPEG Q∈[60,95] | 缺失 | **不符** |
| §4.4 空间几何 | 仿射/透视/弹性（弹性 ≤5–10% 字宽） | 仅旋转 | **部分** |
| §6.1 四级 Test Bench | Clean/Blurry/Reflective/Distorted，**分层标注来自真实照片** | 无分层；60.1% 无模糊、68.1% 无光照；且大纲明文「**Blurry/Reflective 两档不得以该语料打分**」 | **不符** |
| §6.2 cksum valid 与 exact 分开报告 | 是 | 旧 1380 的 cksum 99% 与 full 18% 并存，正说明两者不可互替 | 口径已用对 |
| 内容 plausible（本次 review 新增维度） | 字段须与 ICAO 结构相容 | 随机国籍码 + 非日历日期（90%+）→ 与 syntax mask / 校验位 DFS 对抗 | **不符**（已修：v2 语料） |

**合规结论：14 项条款里 8 项不符、3 项部分不符、0 项达标。** 旧 1380 既不是有效的
训练语料（不物理），也不是有效的验收基准（大纲明文禁止给 Blurry/Reflective 档打分）。

## 3. 距「exact ≥ 90%」还差什么

已知的达成路径（每一步都有今天的实测支撑）：

| 步骤 | 状态 | 依据 |
|---|---|---|
| ① 内容 plausible（k_iso3 池 + 日历合法日期 + 文本零交集） | **已完成** | 旧语料 full 17.75% → v2 73.47% |
| ② 真实照片分层四级 Test Bench（Clean/Blurry/Reflective/Distorted） | 未做 | §6.1 要求，分层来自真实照片 |
| ③ §4.3 物理退化流水线 S1–S8 | 未做（仅加了 blur2/illum80/scale3 的训练专用变体） | 旧语料是准二值 + 退化顺序错误 |
| ④ 训练侧覆盖各退化轴（每轴样本量，而非类别先验） | 部分（v3 只加 8 个变体 ×125 文本） | 五次先验类干预全负（§5 清单） |
| ⑤ 语料与模型的训推一致性（同一渲染 + 同一退化） | 未做 | §5 四项契约 |

**当前 v2 语料的残余弱轴（cnn full）**：blur 0/1/2 → 86.4/68.6/**35.4%**；
illum≥40 → **32.5%**；scale=3 → **49.2%**；rot≠0 → 64.5%。
这四个轴就是「exact 从 73% 到 90%」的差额所在，也是训练侧唯一还没被证伪的杠杆：
**按退化轴扩大样本量**（而不是按类别改先验 —— 那是已翻车清单）。

## 4. 两张照片集是否需要重训

| 集合 | 现状 | 是否需要重训 | 理由（实测） |
|---|---|---|---|
| PassPortPhoto+Photo（50 张 / 41 证件） | cnn both 37/47、crnn 37/47、fuse 37/47；official PASS 37、verified 49 | **训练侧基本无空间** | §8.1 三类归因：错误 20 张是 C 类「校验通过但读错」；§8.3 证 decoder 无空间；本轮 `--pn-weight` A/B 证明位置加权也是负的（目标区 7.16%→9.81%）。剩下的 6 张机位照是**同一份非常规证件**（印成 "POCHN"、个人号区字母密集），把它进训练集会教出非 ICAO 规则 |
| assets/pic（64 张 / 57 证件） | 三引擎 same：both 43/61、official both 49/59 | **需要**，但要换杠杆 | pic 权重集**没有 CRNN 头**（`crnn_weights_available()` 在 MRZ_WEIGHTS_SET_PIC 下返回 0）→ 选 CRNN/融合跑的其实是同一个 CNN 头，这是 pic 侧最大的结构性缺口；且 §7.3 面板显示 pic 的「姓名」字段错误 55/2340（2.35%）、「证件号」23/540（4.26%）集中在字母/数字混淆，属**训练覆盖**问题 |

**pic 侧真正该做的不是重训，而是先补 CRNN 头**（给 pic 权重集单独训一套 CRNN），
否则「融合」在 pic 上是名不副实的。这与 §8.3「fuse 仲裁模式下 CRNN 字符进不了候选集」
的结论一致。

## 5. 50 张集 exact 40/50 还能不能提，与训练什么关系

| 失败构成 | 张数 | 与训练的关系 |
|---|---|---|
| Photo/ 6 张（同一证件） | 6 | **部分相关**：该证件的 pn 区字母密集，模型从未见过这种字形/印刷；但它进训练集会与 44 张标准件的 `P<CHN` 规则冲突 → 需要先定标签口径（是否按 ICAO 归一 'POCHN'→'P<CHN'） |
| 4 张标准件单字符级错误（-U 6、-W 4、-AJ 3、-H 4） | 4 | **相关**：并行会话 §19.5 实测这些格的真值排名常在 rank 2–6（部分超出 top-k）→ 属于「训练覆盖不足 + 字符级判别力」问题，可通过**按退化轴扩样**改善 |
| 已读对但校验位/结构未过 | — | 解码侧，已被 §8.3 证伪为无空间 |

**结论**：50 张的 exact 还有空间，但**不是靠再改一次 loss/先验**（那是第五次翻车），
而是靠 ① 按退化轴扩训练样本量；② 给 pic 补 CRNN 头；③ 把 6 张机位照的标签口径定下来
再决定是否进训练。
